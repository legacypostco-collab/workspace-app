# KAM — итоговая позиция (утверждено)

## Главный тезис
Ценность создаёт **платформа и данные**, а не роль-человек. Покупатель вводит что угодно
(OEM / номер / фото / узел) → получает правильную деталь, дешёвый подходящий вариант,
надёжного поставщика, консолидацию и эскроу — **автоматически, без менеджера**.
Если для пользы нужен отдельный «движок» — значит база неэффективна.

## Роли (без пересечений)
| Роль | Зона |
|------|------|
| **Платформа/софт** | идентификация детали + аналоги, конкуренция на RFQ, консолидация, all-in цена, эскроу/KYB — базовая ценность каждому, автоматически |
| **Покупатель** | self-serve по умолчанию |
| **Продавец** | каталог / поставка (ответы на RFQ) |
| **Оператор** | **ведёт сделку**: исполнение (логистика, таможня, платежи, SLA) |
| **KAM** | **агент привлечения (sales/BD)** — см. ниже |

## KAM = агент привлечения, НЕ сервис-менеджер
Задача — **продавать платформу и заводить на неё клиентов, в приоритете крупных**.

KAM делает:
- продаёт платформу (главное);
- заводит новых клиентов (по ИНН / инвайт / реферал), приоритет — крупные;
- онбордит: помогает освоиться, познакомиться с сервисом;
- дожимает до **активации** (первая сделка);
- получает **маленькую резидуальную комиссию** с продаж приведённых клиентов (% от их GMV).

KAM НЕ делает:
- ❌ не ведёт сделку (её ведёт **оператор**);
- ❌ не занимается ручной оценкой / сорсингом позиций;
- ❌ не исполняет (логистика/таможня/платежи);
- ❌ не «владеет» клиентом как лок-ин.

## Стыковка KAM ↔ клиент — по происхождению (origination)
KAM ведёт тех, кого **сам привёл**: привёл → онбордит → получает маленький % с их продаж,
пока они покупают. Польза клиенту — от платформы; польза от KAM — платформе (канал
привлечения). После онбординга клиент живёт на платформе сам; оператор ведёт его сделки.

Эскалация: оператор может вернуть KAM вопрос по **отношениям с клиентом** (op_escalate_to_kam),
но саму сделку продолжает вести оператор.

## Что построено и как стоит
- ✅ Подходит: заведение по ИНН, инвайт, реферал, начисления (= резидуальная комиссия),
  привязка «кого привёл» (`assigned_kam` = KAM этой сделки для атрибуции комиссии),
  статусы удержания (лид → закреплён).
- 🔄 Комиссия = маленький % с GMV приведённых клиентов (резидуал), не операторский бонус.
- ➖ Снято: ручная оценка off-catalog; «раздача клиентов через пул»; KAM драйвит сделку.
- ➕ Следующее: **онбординг/активация** — провести приведённого клиента от регистрации до
  первой сделки (познакомить, дожать). Комиссия уже привязана к их продажам.

## Кабинет KAM — только необходимое
Заказчики · Мои сделки (read-only, видимость продаж для комиссии/активации) · Начисления ·
Пригласить · Аналитика · Диалоги · Поддержка.
Без: обзора оператора, поставщиков, чертежей, исполнения, составления КП/RFQ.
